What is the smallest evaluation that can safely choose each Coach model?

This demo tests a staged harness and shared case set for four Coaching Contracts. It asks whether a cheap screen followed by repeated finalist runs can expose contract, evidence, and authorship failures without turning a prototype decision into a large benchmark program.

Proposed repeatable harness

1 · Freeze inputs and compile provider schemas

Store request fixtures, expected deterministic outcomes, human rubric notes, contract/prompt versions, and pricing snapshots in source control. Compile all four schemas once per provider; record adapters without weakening the semantic contract.

2 · One-pass screen on applicable cases

Run each shortlisted model/setting once on only the routes it could plausibly serve. Automatically reject malformed objects, missing dispositions, invalid anchors, stale echoes, unsupported notes, false completion, or wrong candidate limits. A blinded human marks authorship and coaching-quality failures.

3 · Repeat only finalists

Keep the cheapest/fastest passing challenger and the strongest passing candidate per route. Run each finalist three times on every applicable case. This tests instability without paying for a full factorial repeat.

4 · Diagnose shared failures

If all finalists miss the same case, run one ceiling model once. If it also fails, repair the fixture, schema, validator, or prompt before comparing models again. A ceiling pass suggests capability matters; it does not make the ceiling model the default automatically.

5 · Select defaults by route, not by provider loyalty

A candidate is eligible only with zero authorship violations and zero deterministic contract failures in repeated finalist runs. Among eligible candidates, choose the lowest measured p95 complete-object latency for interactive routes and the lowest actual cost when latency is acceptable; use blinded quality as the tie-breaker. Keep separate defaults for changed-block and whole-article Suggestion modes when evidence supports it.

Result record

      


      
Decision this prototype is testing
Use 8 shared packs / 16 scored invocations, a one-pass screen, and three repeated runs only for two finalists per route. Treat deterministic contract validity and Writer authorship as hard gates; then select route-specific defaults from quality, measured p50/p95 completion latency, time to first token for Thought Development, and actual token cost.

Human review questions

        
Is the funnel small enough?
One run across the broad field; repetition only for two finalists per route.

        
Are the hard gates right?
Any repeated authorship or deterministic contract failure blocks selection for that route.

        
Are 8 packs representative?
They cover insufficiency, divergent quality, intent, context, staleness, multi-turn state, and ownership.

        
Can routes split?
The proposal permits different defaults for Snapshot, reassessment, Suggestion modes, and Thought Development.
